# Task t2: Auto-refresh when a window's `resetsAt` passes

## Goal
Trigger an immediate provider refresh on the existing `Poller` schedule timer as soon as any of that provider's windows crosses its `resetsAt` timestamp, without adding a new timer and without looping when a provider hasn't rolled over yet.

## Allowed files to edit
- `Sources/AIUsageCore/MenuModel.swift`
- `Sources/AIUsage/Poller.swift`
- `Sources/CoreChecks/ModelChecks.swift`

## Required Interfaces & Behavior
1. In `Sources/AIUsageCore/MenuModel.swift` (`enum Schedule`):
   - Add:
     ```swift
     public static func nextReset(in runs: [ProviderRun], after started: Date) -> Date?
     ```
     Returns the earliest `window.resetsAt` strictly `> started` across all `.success` reports in `runs`. Ignores `.failure`, `nil` results, and `resetsAt <= started` (prevents infinite tight refresh loop if provider returns stale past reset time).
   - Add:
     ```swift
     public static func nextRun(started: Date, interval: Int, failures: Int, resetsAt: Date? = nil) -> Date
     ```
     Computes `let scheduled = started + delay(interval: interval, failures: failures)`. When `failures == 0`, `let resetsAt`, `resetsAt > started`, and `resetsAt < scheduled`, returns `resetsAt`; otherwise returns `scheduled` (failing providers keep exponential backoff).
   - Extend `Schedule.isDue` with a defaulted parameter (preserving existing callers):
     ```swift
     public static func isDue(started: Date, interval: Int, failures: Int, now: Date, resetsAt: Date? = nil) -> Bool
     ```
     Returns `nextRun(started: started, interval: interval, failures: failures, resetsAt: resetsAt) <= now + 1`.
2. In `Sources/AIUsage/Poller.swift`:
   - Add private helper `resetDate(for configId: String, after started: Date) -> Date?` calling `Schedule.nextReset(in: runs.filter { $0.configId == configId }, after: started)`.
   - Use `Schedule.nextRun(started: state.started, interval: interval, failures: state.failures, resetsAt: resetDate(for: id, after: state.started))` in `nextRefresh` (around lines 31-37).
   - Use `Schedule.isDue(started: state.started, interval: interval, failures: state.failures, now: now, resetsAt: resetDate(for: id, after: state.started))` in `tick()` (around lines 106-122).
